## Code (off by default)

- `blind_insertion/perception/zed_estimator.py`: **estimator key = the gate.** A gate checkpoint may name its pose nets (`pose_nets`, files next to the gate). Then `ZedEstimator` loads those nets, not the `pose` / `pose2` arguments. A pose checkpoint may carry `nominal_port_xy` and `zed_crop`; without them `NOMINAL_PORT_XY` (220, 360) mm and `ZED_CROP` (110, 70, 160) apply. The estimator refuses a pose pair or a gate with a different nominal or crop. So `chain_args.zed_gate: "zed_v5_gate"` selects the whole estimator. chain.py, eval_chain.py, netcache.py and the checks are unchanged; they pass the gate name as before.
- Old nets and keys behave the same: v1 + `zed_v1_gate_arm` through the new code reproduces the logged rig estimates to 0.002 mm (n = 72 real frames, 2026-11-01..11).
- `scripts/perception/train_zed_gate_v2.py`: skip an empty finger-opening bin in its report (needed for a gate fit at one arm pose). No other change.
- `scripts/eval/zed_placement.py`: option `--pc-poses` (a JSON pose list); the default sweep is unchanged.
- New: `scripts/perception/train_zed_v5.py`, `train_zed_gate_v5.py`, `check_real_zed_v5.py` (real-frame check, v1 against a new key, and the zed_gt spots), `scripts/eval/zed_placement_summary.py`.

## Rig runbook: capture-only gate mapping (needs no approval: no motion beyond the capture pose)

Purpose: real ZED frames with a known PC pose, to decide between v1 and v5 and to train a real-frame fine-tune. Do it before any placement full run.

```bash
sha256sum runs/perception/zed_v5s0.pt runs/perception/zed_v5s1.pt runs/perception/zed_v5_gate.pt   # match the table
for C in deploy/config/bimanual_align8_nojump_retry2_rzv2.json deploy/config/bimanual_align8_zedv5.json; do
  .venv/bin/python -m deploy.checks.bimanual_conventions --config $C | tail -1                       # FAILED: none
done
# per pose: move the PC (tape marks, ruler +/-1 mm, yaw from two marks +/-1 deg), then both captures:
S='{"port_xy": [0.241, 0.394], "yaw_deg": 4, "method": "tape shift", "unc_mm": 1}'
.venv/bin/python -m deploy.run_bimanual --stage capture --config deploy/config/bimanual_align8_nojump_retry2_rzv2.json --name map_v1_dx+10 --pc-spot "$S"
.venv/bin/python -m deploy.run_bimanual --stage capture --config deploy/config/bimanual_align8_zedv5.json         --name map_v5_dx+10 --pc-spot "$S"
```

- Poses, in this order: real (measure it with the tape and the case-edge fit as for data/zed_gt), x +/-10, y +/-10, yaw +5, +10, x +/-20, y +/-20, yaw -10, +15. Then, if time allows, (+/-25, +/-25, +/-15) corners.
- At a rejected gate, answer Enter (stop), never `c`.
- Read `estimate zed_pc` (port_xy, yaw_deg, ok, mahalanobis, disagree_xy_mm) in each run's events.jsonl. Afterwards on mason: `check_real_zed_v5.py` on the new frames with the tape poses as truth.
- Pass (for v5 to go to full runs): at every pose, gate ok and |estimate - tape| <= 3 mm, <= 1.5 deg, and at the real spot v5 within 3 mm of v1.
- Stop the mapping when the reject or the error pattern is clear; it needs no full run.
