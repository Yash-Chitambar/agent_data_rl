# Running the remaining training on a GPU server or cluster

How to move the multi-day RL training (Phases B to F of `docs/archive/RESEARCH_PLAN_single_arm.md`) from the local
RTX 3090 Ti to (a) a multi-GPU Linux box reached over SSH, or (b) a SLURM cluster. Everything
lives in `scripts/server/`. Written 2026-10-20 against the code as of commit 7d8445e.

| File | What |
|---|---|
| `scripts/server/bootstrap.sh` | Idempotent setup on a fresh machine + verification + smoke runs |
| `scripts/server/verify.py` | Import, version, GPU (torch and Warp), EGL and MuJoCo Warp checks |
| `scripts/server/env.sh` | Environment for every job (`PYTHONPATH`, `MUJOCO_GL`, uv and Warp cache paths) |
| `scripts/server/run_jobs.py` | Multi-GPU job runner for a plain box (no scheduler) |
| `scripts/server/slurm/submit.sh`, `job_array.sbatch` | Manifest -> SLURM job array, one line per task |
| `scripts/server/slurm/node_runner.sbatch` | Alternative: whole node(s) running `run_jobs.py` |
| `scripts/server/jobs/*.txt` | Job manifests per phase (generated by `jobs/make_manifests.py`) |
| `scripts/eval/ood.sh`, `eval/phase_e.sh` | Eval wrappers used by the C and E manifests |
| `scripts/server/sync_up.sh`, `sync_down.sh` | rsync code/runs up, runs/results down |
| `scripts/server/container/Dockerfile`, `Apptainer.def` | Optional OS layer (untested) |

## 1. Before migrating (checklist)

- [ ] **Commit and push** the new files: `docs/operations/SERVER.md`, `scripts/server/` (all of it), and the
      `CLAUDE.md` paragraph. The server gets the code by `git clone`; anything uncommitted
      (e.g. the gear-task files another agent is writing) is not there unless pushed or sent
      with `sync_up.sh`.
- [ ] **Decide the server type** (plain box: §4; SLURM: §5) and check its GPUs meet §2
      (CUDA 13: driver >= 580 and compute capability >= 7.5; older GPUs such as V100/P100 and older
      drivers (>= 525) use the CUDA 12 stack, which `bootstrap.sh` selects automatically).
- [ ] **GitHub access** to the private repo from the server (§3.1): `gh auth login`, a read-only
      deploy key, or a fine-grained PAT. The submodules (mjfit, robosimstudio) and Menagerie
      are public.
- [ ] **De-duplicate with the local queue.** `runs/queue/jobs.txt` still contains
      `B-peg-proprio-base-s2`, `B-peg-proprio-nocontact-s1` and `E-usbc-proprio-curr-s0`
      (tagged `also_in_local_queue` in the server manifests). Remove them from one side, or they
      train twice. `C-peg-proprio-base-s0` is training locally and is not in the server manifests.
- [ ] **Decide where the evals of local runs happen** (§8): blind s1, no-contact s0 and C base s0
      were trained locally. Either evaluate them locally (`scripts/eval/phase_b.sh` /
      `eval/phase_c.sh`, ~10-20 min each), or push them (`sync_up.sh --runs ...`) and mark them
      complete on the server (`run_jobs.py --mark-complete NAME`). Lines that need this are tagged
      `needs_local_ckpt`.
- [ ] **Gate C before D/E with noise.** The D manifests and the E `noise` ablation use a
      placeholder noise model `{"q_noise": 1e-4}` (`NOISE` in `jobs/make_manifests.py`). After
      Gate C picks the level, edit `NOISE` and regenerate (§6).
- [ ] **Re-validate the manifests** after any change to `train.py` / `eval.py` (another agent is
      editing them): `.venv/bin/python scripts/server/jobs/make_manifests.py --check` parses every
      command with the real argparse parsers and checks every `env_json` key against `EnvCfg`.
- [ ] For a preemptible cluster or runs longer than the time limit: implement **resume** first
      (§9.1). Without it, a preempted run restarts from zero.
- [ ] Nothing large needs excluding from git: `runs/`, `third_party/`, `.venv`, `.cache`,
      `.python` are already gitignored; `results/` (~6 MB) and `docs/` (8 MB, mostly the paper PDF) are committed.

## 3. Bootstrap

### 3.1 Get the code (primary path: git clone)

The repo is private: <https://github.com/Yash-Chitambar/peg_test> (branch `main`). Pick one:

1. **gh CLI** (simplest, personal machine): `gh auth login` (device-code flow, choose HTTPS),
   then `gh auth setup-git`. Credentials are your user's; do not do this on a shared account.
2. **Deploy key** (read-only, per repo; best for a shared server or cluster):
   `ssh-keygen -t ed25519 -f ~/.ssh/peg_test_deploy -N ''`, add the `.pub` under
   GitHub repo Settings -> Deploy keys (read-only), then in `~/.ssh/config`:
   ```
   Host github-peg
     HostName github.com
     IdentityFile ~/.ssh/peg_test_deploy
     IdentitiesOnly yes
   ```
   and clone `git@github-peg:Yash-Chitambar/peg_test.git`. Submodule URLs are public HTTPS,
   so they need no key.
3. **Fine-grained PAT** (read-only "Contents" on this repo, with an expiry):
   `git clone https://<user>:<token>@github.com/Yash-Chitambar/peg_test.git`; afterwards
   `git remote set-url origin https://github.com/Yash-Chitambar/peg_test.git` so the token is
   not left in `.git/config`, and use a credential helper for pulls.
4. **SSH agent forwarding** from your laptop (`ssh -A server`, clone with `git@github.com:...`):
   no key on the server, but only while you are connected.
5. No GitHub access at all: `scripts/server/sync_up.sh user@host:/path/peg_test` (rsync, no
   `.git`; then `train.py` records `git: "nogit"` in `config.json`, so prefer 1-4).

```bash
git clone --recurse-submodules https://github.com/Yash-Chitambar/peg_test.git
cd peg_test
bash scripts/server/bootstrap.sh          # or: --no-egl, --skip-smoke, --skip-install
```

### 3.2 What bootstrap.sh does

1. Checks the driver and the GPUs' compute capability, selects the CUDA 13 or CUDA 12 stack, and checks free disk. In CUDA 12 mode it installs the locked env, then swaps in torch cu126 and Warp cu12; afterwards never run `uv sync`/`uv run` by hand on that machine (they restore the cu130 wheels).
2. Installs uv 0.12.18 into `~/.local/bin` if `uv` is not on `PATH`.
3. `git submodule update --init --recursive` (mjfit, robosimstudio at the pinned commits).
4. `uv python install 3.12` and `uv sync --locked --inexact --group train` (`--inexact` never
   removes packages, so it is safe on an existing `.venv`; locally it reports "Would make no
   changes"). uv and Python caches go to `.cache/uv` and `.python` inside the repo (`env.sh`).
5. Menagerie sparse clone into `third_party/mujoco_menagerie` (blob-less, cone mode):
   exactly `flexiv_rizon4s`, `robotiq_2f85`, `i2rt_yam`, at commit `cda5236f` (the local one).
   If the clone exists it only fixes the sparse set or the commit.
6. `verify.py`: versions (MuJoCo 3.12.0, MuJoCo Warp 3.12.0, Warp 1.18), torch sees CUDA
   (matmul), Warp sees the GPU, blind_insertion imports and finds the Menagerie robots, an EGL
   render of a 64x64 test scene, and a 64-world MuJoCo Warp step. Results in `runs/_verify.json`.
7. Smoke runs (writes `runs/_smoke-*`, which `sync_down.sh` skips):
   `train` 256 worlds x 2 PPO iterations, `eval` of that checkpoint (64 episodes),
   `train_visual` 128 worlds x 2 iterations. Locally: 21 s + 21 s + 31 s on a warm kernel cache.
   **The first run on a new GPU architecture compiles all Warp kernels** (several minutes);
   the default per-step timeout is 900 s (`SMOKE_TIMEOUT`).

Exit status is non-zero if any step fails.

### 3.3 Optional container

`scripts/server/container/Dockerfile` and `Apptainer.def` give an Ubuntu 24.04 OS layer with
git, rsync, uv, glvnd/EGL and the NVIDIA EGL vendor file; the Python env is still built by
`bootstrap.sh` inside the bind-mounted repo (always mount it at the same path, `/work/peg_test`,
because `.venv` refers to `.python` by absolute path). The driver comes from the host
(`docker --gpus all` with the NVIDIA container toolkit and `NVIDIA_DRIVER_CAPABILITIES` including
`graphics`; `apptainer --nv`). **Untested** (not built locally). Use it if the host's glibc is too
old, or EGL libraries are missing and you cannot install packages.

### 3.4 Warp kernel cache

Warp compiles kernels on first use and caches them under `$WARP_CACHE_PATH/<warp version>`
(`env.sh` default: `$HOME/.cache/warp`, which is Warp's own default; ~90 MB locally). The cache is
per GPU architecture and kernel hash; the CUDA graph (20 substeps) is recaptured in every process
regardless. On a cluster, fill the cache once (run `bootstrap.sh` on a compute node of each GPU
type) before submitting a large array, so 100 tasks do not compile at once; if the shared home
file system is slow, set `WARP_CACHE_PATH` to node-local scratch and copy the filled cache there in
the job. No code change is needed for this (`WARP_CACHE_PATH` is read by `warp.init()`).

## 4. Running on a multi-GPU box (no scheduler)

```bash
tmux new -s jobs            # survives SSH disconnects; detach with C-b d, reattach: tmux a -t jobs
cd ~/peg_test
python3 scripts/server/run_jobs.py scripts/server/jobs/B_train.txt scripts/server/jobs/B_eval.txt
```

- One job per GPU by default; all GPUs from `CUDA_VISIBLE_DEVICES` or `nvidia-smi`. Choose with
  `--gpus 0,1,2,3`, pack with `--per-gpu 2` (e.g. two 11 GB blind jobs on a 40-80 GB GPU; measure
  throughput first: one blind job already keeps a 3090 Ti at ~97% utilization, so packing mainly
  helps when the GPU is much larger than the job, and for small eval jobs).
- Each job runs as `bash -c "<line>"` from the repo root with `env.sh` sourced and
  `CUDA_VISIBLE_DEVICES=<gpu>`. The code always uses `cuda:0`, which is then that GPU.
- On shared servers, pass explicit `--gpus 0,1 --require-idle-gpus`. Before each launch,
  the runner checks three samples one second apart, then rechecks immediately before
  changing run state. A GPU needs <1 GiB allocated, <=1% compute and no compute PIDs.
  Busy GPUs or failed capacity queries leave the job queued; the runner waits and checks
  again. This option requires `--per-gpu 1`. It does not reserve a GPU against other
  users; use the cluster scheduler when one is available.
- Lines may end with annotations after ` # ` (ignored by bash, so the format stays the same as
  `runs/queue/jobs.txt`): `after=RUN[,RUN]` (start only after `runs/RUN/.complete` exists),
  `visual`, `mem=GB`, `est_h=hours`. Manifests are re-read every poll, so appended lines are picked
  up; `--watch` keeps the runner alive when idle.
- A training job that exits 0 gets `runs/<name>/.complete` (JSON). Jobs in
  `runs/queue_server/done.txt` or with a `.complete` marker are skipped (`--force` overrides).
  Failed jobs are retried once (`--retries`); a training retry resumes from `runs/<name>/last.pt`
  (`--resume` is appended at launch), or moves a dir without `last.pt` to `runs/<name>.failed-<time>`. Permanent failures go to `failed.txt`, and jobs
  depending on them are reported as `blocked`.
- Logs: `runs/queue_server/runner.log` (events, and the tail of the job's log on failure),
  `runs/queue_server/jobs/NNNN-<name>-aK.log` (per attempt), and the job's own `runs/<name>.log`.
- `--status` prints each job's state; `--dry-run` shows what would start where;
  `--only REGEX`, `--max-jobs N` limit what starts.
- Ctrl-C or `kill <runner pid>` stops the runner **and its jobs** (not marked done). The runner
  ignores SIGHUP and starts jobs in their own sessions; if the runner itself dies hard
  (`kill -9`), a restarted runner re-adopts still-running jobs from `jobs/running.json` and reads
  their exit codes from `jobs/rc/`. Only one runner per state dir (lock file).
- Without tmux: `nohup python3 scripts/server/run_jobs.py MANIFEST... > runs/queue_server/nohup.out 2>&1 &`.

Monitoring: `python3 scripts/server/run_jobs.py MANIFEST... --status`,
`tail -f runs/queue_server/runner.log`, `grep sps runs/<name>.log | tail -1`, `nvidia-smi`.

Suggested order (each command drains its manifests, then exits):
```bash
R="python3 scripts/server/run_jobs.py"
J=scripts/server/jobs
$R $J/B_train.txt $J/B_eval.txt $J/C_train.txt $J/C_eval.txt     # ~130 GPU-h
$R $J/E_train.txt $J/E_eval.txt                                  # after Gate C noise decision
$R $J/D_train_tier1.txt $J/D_eval.txt                            # D eval lines of tier 2 wait
$R $J/D_train_tier2.txt $J/D_eval.txt
```
Evals and training can be in one invocation: an eval line waits for its `after=` run, and a free
GPU takes the next ready line in file order.

## 5. Running on SLURM

```bash
# training array: one task per line, at most 16 at once
scripts/server/slurm/submit.sh scripts/server/jobs/C_train.txt \
    --partition gpu --account myacct --gres gpu:1 --cpus 8 --mem 48G --time 06:00:00 --max-parallel 16
# evals start when the training array has ended (afterany); tasks whose run is not complete exit 3
scripts/server/slurm/submit.sh scripts/server/jobs/C_eval.txt --after <train array job id> --time 01:00:00
```
(Options go after the manifest. `--dry-run` writes the frozen manifest and prints the `sbatch`
command without submitting.)

- `submit.sh` freezes the manifest to `runs/slurm/manifests/<name>-<time>.txt` (only command lines,
  leaving out runs that already have `.complete`), and submits `job_array.sbatch` with
  `--array=1-N%K`. Task i runs line i. Logs: `runs/slurm/<name>-<jobid>_<task>.out` plus the
  job's own `runs/<name>.log`.
- Task logic (`job_array.sbatch`): skip if `runs/<name>/.complete` exists; exit 3 if an `after=`
  dependency is not complete; move a partial run dir aside; run; write `.complete` on success.
  Re-running `submit.sh` on the same manifest resubmits only what is missing.
- Time limits: blind 300M = 2.2-2.4 h on a 3090 Ti; ask for >= 2x on unknown GPUs
  (`--time 06:00:00`), visual jobs `--time 12:00:00` (stop rule usually ends them at ~1.7 h, the
  300M cap would be ~10 h), USB-C `--time 08:00:00` (throughput not measured yet), evals 1 h.
  Use `--only visual` / `--only 'train_visual'` to submit the visual lines separately with a longer
  limit.
- **Preemption / requeue:** the template sets `--requeue`, so a preempted task is requeued by
  SLURM (if the cluster's `PreemptMode=REQUEUE`) and resumes from its last checkpoint (§9.1).
  `--signal=B:USR1@300` delivers USR1 300 s before the time limit; the task only logs it, unless
  `BI_REQUEUE_ON_TIMEOUT=1` is exported, which requeues the task to continue from the checkpoint.
- One task = one GPU. To pack several jobs per GPU, or if the cluster prefers whole nodes, use
  `sbatch --gres=gpu:8 ... scripts/server/slurm/node_runner.sbatch MANIFEST... [--per-gpu 2]`, which
  runs `run_jobs.py` inside the allocation (shared state in `runs/queue_server/`).
- Containers: prefix the command in `job_array.sbatch` (`bash -c "$cmd"`) with
  `apptainer exec --nv --bind $PWD:/work/peg_test --pwd /work/peg_test peg-test-os.sif`.
- The repo (with `.venv`) must be on a file system visible from compute nodes. If `$HOME` is
  small, clone into project/scratch space; set `UV_CACHE_DIR` there too (env.sh puts it in the repo).

## 6. Job manifests

Generated by `python3 scripts/server/jobs/make_manifests.py` (edit the generator, not the
`.txt`; `--check` validates every command against the real parsers). Training lines are ordered
seed 0 of every condition, then seed 1, then seed 2, so a partial pass already gives one seed of
everything. GPU-hours are **3090 Ti-equivalent**, from the local queue log: blind 300M at 12,288
worlds = 2.2-2.4 h (36-38k env steps/s incl. PPO, both robots) -> 2.3 h; visual with the stop rule =
1.7 h (8.5k steps/s, stopped at 50M; 300M cap ~9.8 h); USB-C **assumed** 3.0 h (not measured);
`eval/phase_b.sh` = 0.18 h (measured), `eval/phase_c.sh` ~0.35 h, one eval ~0.04 h. An A100/H100
may not be much faster per job (the physics is many small kernels); measure with the first job.

Notes on the choices (all flags verified against argparse; see also §9):
- Phase D start offsets: `peg_offset` is the per-axis uniform half-width `a`; the median radial
  offset is 0.765 `a` (`train.MEDIAN_RADIAL_PER_HALFWIDTH`). Scaled regime: median = opening/6

- Phase E evals must pass `--peg_offset` explicitly: `phase_e_usbc_up.json` does not set it, so
  `eval.py` would otherwise use the peg default (12.5 mm half-width, ~10 mm median).
- E1 as configured has **no noise model** (`phase_e_usbc_up.json`), so the plan's "no noise model"
  ablation is E1 itself; `E-usbc-proprio-noise-*` is the with-noise counterpart. If Gate C decides
  E1 should include noise, add it to the config instead.
- Phase C "training with the noise randomized" is implemented as training at a fixed level per
  run (EnvCfg holds one value; per-world ranges would need code, §9).
- Phase C noise on q only; `qd_noise` exists but the plan gives no level, so it stays 0.
- Not in any manifest: C-R3/D/E7 probes (need code), §10.2 per-cell F_min/PNR (CPU checks, need
  `--family` in `signal_checks.py`), E5 latch, E6 E-side, chamfer ablation, the gear task
  (being added by another agent), and A/B items already done.

## 7. Verification on the server

Speed and memory before long runs: `bash scripts/server/benchmark.sh --gpu <free index> [--visual] [--nworld N]` writes `runs/_bench/*.json` (steps/s, peak GPU memory).


1. `bash scripts/server/bootstrap.sh` ends with `ALL OK`.
2. Throughput at full size (no training, ~2 min):
   `source scripts/server/env.sh; $PY -m blind_insertion.checks.a_s9_throughput --ns 4096,12288 --out runs/_a_s9.json`
   (local 3090 Ti: 34k / 43k env steps/s physics only).
3. Pilot: `python3 scripts/server/run_jobs.py scripts/server/jobs/B_train.txt --max-jobs 1` and
   after ~5 min check `grep sps runs/<name>.log | tail -1` (local ~37k for blind) and
   `nvidia-smi` memory (~11 GB). Scale the GPU-hour estimates by local_sps / server_sps.
4. After the first run finishes: `runs/<name>/.complete` exists, `train_log.csv` reaches 300M
   steps, and its eval line starts.
5. Reproducibility sanity (MuJoCo Warp is not bitwise deterministic, A-S8): compare the server's
   blind s2 training curve and eval success with s0/s1 (distribution-level, not bitwise).

## 9. Code changes for the migration (done 2026-10-21 on `main`)

All items below were open when this file was written; they are now implemented and tested on
athena5 (small runs; see `docs/campaign/FINDINGS.md` 2026-10-21).

### 9.1 Resume -- done
`train.py` and `train_visual.py --resume` continue from `runs/<name>/last.pt`: model, Adam state,
iteration, env steps, best score, wall time, curriculum stage, and the torch / CUDA / env RNG states.
`train_log.csv` is rewritten up to the checkpoint's iteration and then appended (no duplicate rows).
Checkpoints written before this change (no optimizer or RNG state) resume too: the curriculum stage
is then read from `curriculum.json`. With `--resume`, a run that has `DONE` with at least `--steps`
steps (or stopped by the success rule) exits at once; a larger `--steps` extends it.
`run_jobs.py` and `slurm/job_array.sbatch` append `--resume` at launch when a run dir without
`.complete` holds `last.pt` (the manifest text is unchanged, so running jobs still match); a partial
dir without `last.pt` is still moved to `runs/<name>.failed-<time>`. `BI_REQUEUE_ON_TIMEOUT=1` is
now safe on SLURM: each requeue continues from the last checkpoint (every 25 iterations).

### 9.2 Atomic checkpoint writes -- done
`train.save_atomic`: `last.pt`, `best.pt` and `ckpt_*.pt` go through `<file>.tmp` + `os.replace`.

### 9.3 Completion marker and run directory -- done
`runs/<name>/DONE` (JSON: steps, iter, wall_s, reason `steps` | `stop_success`, success) is written
at the end of training. `BI_RUNS_DIR` moves the run directory (default `runs/`). The runners still
write their own `.complete`.

### 9.4 Flags for the remaining phases -- done
- `train_visual.py`: `--env_file --family --curriculum --variant_kw` (built with `train.make_env`
  and `train.Curriculum`), `--modality rgb|depth|rgbd`, `--proprio` (joint-history TCN fused with the
  image TCN, latents concatenated before the actor and the contact decoder, plan §12.2), `--resume`.
  Depth uses `EnvCfg.depth_model` (min range 7 cm as the D405 on the YAM, noise growing with d^2,

  `blind_insertion/configs/phase_f_usbc.json`. Route: direct RL (plan §12.3 route 1); measured
  10.3 GB at 1,024 worlds (RGB-D + proprio, USB-C).
- `analysis/probes.py` and `eval.py` share `eval.add_env_args` / `eval.env_kwargs`: `--env_file
  --env_json --family --clearance --peg_offset --ood --variant_kw`.
- `checks/signal_checks.py`: `--env_file --env_json --family study|usbc|scale:o:c --clearance
  --press --noise` (robot, gains, pads and grip force from the env config).
- `EnvCfg.noise_rand`: per-world levels drawn at every reset for `q_noise`, `qd_noise`,
  `q_quant_bits`, `backlash_arcmin` (per-world `jnt_range` of the backlash hinges) and `latency`.

### 9.5 GPU selection, caches, machine-specific bits
- GPU choice: only through `CUDA_VISIBLE_DEVICES` (what both runners set). `EnvCfg.device`
  defaults to `"cuda:0"` and every tensor follows `env.device`, so `--env_json '{"device":"cuda:1"}'`
  probably works for `train.py`/`eval.py`, but it is untested (Warp CUDA-graph capture, `torch`
  current device); `checks/a_s9_throughput.py` hard-codes `device="cuda"`. A `--device` flag is
  optional; keep using `CUDA_VISIBLE_DEVICES`.
- Warp kernel cache: configurable through `WARP_CACHE_PATH` (no change needed; §3.4).
- No absolute paths or `/tmp` use in `blind_insertion/` (paths are relative to the repo root via
  `Path(__file__)`; Menagerie at `ROOT/third_party/mujoco_menagerie`). Entry points must run with
  the repo root as cwd (`MUJOCO_LOG.TXT` and relative `--env_file` paths).
- `git_hash()` records `"nogit"` when the code was rsynced without `.git` (prefer `git clone`).
- `scripts/eval/phase_c.sh` uses the system `python3` to build the gains JSON (needs python3 on
  `PATH`; it is on every server we would use).
- The plan's 50M-step rollout videos (§3.4) are not produced by `train.py` (not a migration issue).

## 10. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `torch.cuda.is_available()` False | driver < 580, or `CUDA_VISIBLE_DEVICES` empty |
| `no kernel image is available` | GPU older than sm_75 with the CUDA 13 stack: re-run `bootstrap.sh --cuda12` (or someone ran `uv sync`) |
| first job slow to start (minutes) | Warp kernel compile on a new GPU type; later runs hit the cache |
| EGL errors in `verify.py` | install `libegl1` / `libglvnd0` and make sure the NVIDIA EGL library and `/usr/share/glvnd/egl_vendor.d/10_nvidia.json` exist; or `--no-egl` (training does not need EGL) |
| `ov_nefc`/`ov_narrow` > 0 in `train_log.csv` | constraint/contact buffer overflow: raise `njmax`/`nconmax` via `--env_json` |
| eval job exits 3 on SLURM | its `after=` run has no `.complete` yet (submit evals with `--after <train job id>`) or the run was trained elsewhere (`run_jobs.py --mark-complete NAME`) |
| job trains twice | also in the local `runs/queue/jobs.txt` (`also_in_local_queue`) |
